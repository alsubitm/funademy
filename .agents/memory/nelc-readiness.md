- NELC (المركز الوطني للتعليم الإلكتروني) + TVTC issue a **unified license** for Saudi e-training platforms; licensed platforms can then apply for **technical integration with FutureX** (the national platform) to publish programs.
- nelc.gov.sa and futurex.nelc.gov.sa block automated fetching (Cloudflare) — use search snippets, don't retry webFetch. The FutureX wizard lives at services.futurex.sa (login required).
- Site stance: never claim a license before issuance. `NELC_LICENSE_NO` constant is the single switch — empty ⇒ /nelc page + footer say «قيد الإعداد». **Why:** licensing claims are legally sensitive; one constant prevents stale/false claims scattered in copy.
- Compliance surface = /privacy, /terms, /nelc (+ /en mirrors). Owner must review refund/support wording before relying on it legally.

## LRS verification test (wizard step 2)
- Authority order for statement shapes: **wizard violation list > wizard's PASSED per-org `registered` example (keep byte-for-byte) > github.com/nelc/laravel-lrs-package `src/Interactions/*.php`** — generic xAPI/cmi5 docs are outright wrong. **Delivery ≠ verification:** statements the LRS stores fine (HTTP 200) can still fail rules. Copy odd example strings verbatim (`Https://funademy.io` capital H; duration `PT30H00M00S`); NO `context.registration`; en-US-only language maps everywhere.
- The verifier applies PER-STEP rules mirroring NELC's own package, not one uniform shape (2026-08-10 run: uniform example-clones got has_data but rejected 23/29). The rules: course description + the duration/lms_url/program_url extensions live ONLY in `registered` (CTX001/CTX002/CRS008 — every other statement carries ONLY the platform extension); sub-verbs need their OWN objects with package activity types (watched→video, completed lesson→lesson, attempted→tincan unit-test, completed unit→adl module, earned→opigno certificate) with IRIs derived from the course IRI and the course as their single `contextActivities.parent` (CRS003); `rated` must carry `result.response` text + score bounds 0–5 (ASM004). The single-course-id rule applies to course-LEVEL statements; sub-activities point back via parent.
- **A national ID with ANY delivered journey is permanently burned:** the LRS never deletes, so the verifier will always see old statements alongside new ones — resending to a used ID can NEVER pass. Confirmed 2026-08-10: post-fix sends were clean, but the report still showed all six codes because a pre-fix journey existed under the same ID. Diagnose rejected reports by comparing the checker's statement count with the audit-log send timeline before assuming shape bugs.
- **SEQ003 (duplicates) is procedural, not a shape:** send the journey exactly ONCE per national ID — the verifier counts a re-send as duplicate statements and rejects, then demands a FRESH national ID for the next attempt. Fresh UUIDs only make wizard re-CHECKS safe. Guard duplicate sends server-side via `findPriorJourneySignal`: (1) **delivered guard** — block when a delivered ok:true row exists (ID permanently burned, `delivered:true`); (2) **live-run guard** — block if an unexpired unconsumed journey run already exists (pending send, `delivered:false`). Both return `409 duplicate_journey`; `confirmDuplicate:true` bypasses both; failed-only sends don't count (nothing reached the LRS). Confirmed 2026-08-10: a double-click sent the journey twice for a fresh ID, producing 10×2=20 duplicate statements and a SEQ003 rejection even though all shapes were correct (28/29 rules passed).
- The LRS keeps old non-conforming statements forever, so raw read-back counts overstate what the verifier sees — judge readiness only by per-step contract classification (one shared classifier for builder, self-check, and tests). The shared contracts pin EXACT texts AND result values (deep equality); any looseness lets altered statements read as "ready" — a false government-verification signal. Read-back queries need `related_activities=true` (sub-activity statements reference the course only via contextActivities.parent).
- Never fake success when LRS credentials are missing — falsely "passing" a government verification is the worst failure mode. Wizard step 3 (production) = same code, different NELC_LRS_* values; no separate build.

## Geo-block → who can send, and what the audit log can honestly claim
- lrs.nelc.gov.sa (Cloudflare) rejects ALL non-Saudi datacenter egress with an HTML 403 block page — credentials/headers irrelevant. US-hosted servers can never POST to it directly, and can never CONFIRM delivery either.
- **Decision:** the staging test is sent from the owner's browser (device inside KSA). Consequences to preserve: browser-reported outcomes must stay labeled "unverified server-side" (NELC's wizard check is the real authority), and the LRS Basic credential handed to the browser is an explicitly accepted, documented risk — acceptable ONLY because the app has a single admin (the owner, whose own credential it is), handing it over requires re-entering the admin password (step-up beyond the session cookie), and the credential is scoped to the platform's own LRS store. Never expose it to non-admin users; production auto-sending of real learner events needs NELC IP allowlisting or KSA egress instead.
- Real LRS creds may exist in the workspace env → test suites must explicitly clear NELC_LRS_* per test, and any live-send spec must require an explicit opt-in flag AND an explicitly supplied national ID (never a default ID in source — PII).

## Pre-send burned-ID check (SEQ003 layer 2)
- Admin send now pre-queries NELC's LRS AGENT-ONLY (no activity filter — any course/any environment burns an ID) via a record-free `precheck` action; classification is fail-closed: only literal HTTP 200 with `statements: []` and no `more` cursor counts as clean.
- EXPECTED behavior, not a bug: staging creds are write-only, so the precheck usually answers "unverifiable/read_denied" → the UI demands explicit confirmation. Never "fix" this into a silent pass.
- Override grants are bound to the exact national ID they were raised for (typed-ID confirm for burned/delivered cases); form edits dismiss prompts; LRS reads use cache:no-store.

## Production outbox (real learner data → NELC prod LRS)
- Statement UUID is the xAPI idempotency key — an LRS stores a statement id at most once. The outbox freezes each statement JSON (with its id) at enqueue time; retries/duplicate transports can never duplicate a record. Never rebuild a statement on retry (fresh UUID = real duplicate).
- Two transports, one queue: server flush (works only if NELC ever allowlists; WAF geo-blocks US egress) + admin browser relay. Browser prepare "leases" its rows via the unconsumed/unexpired flush-run; the server PAUSES at the first leased row (ordered delivery — never skip past). **Why:** overlap would reorder or double-send in flight.
- `outboxActive()` gates ENQUEUE, not just delivery — dev preview shares the prod DB/secrets, and test kids must never reach NELC's store. Delivery failure is invisible to kids/parents by design (enqueue+flush swallow errors).
- Progress/completion sent to NELC are band-scoped: a child's curriculum for a subject IS their band's units; percent counts only published in-band lessons. Without the band filter a multi-band subject misreports % and completed_course.
- Any module reachable from Next.js instrumentation.ts is also bundled for the edge runtime → node builtin imports (`import 'crypto'`) break the whole dev server with Module-not-found. Use Web Crypto globals (`crypto.randomUUID()`).
- `timeSpentSeconds` is client input: clamp at the API boundary (0..4h int) AND in the duration builder — NELC durations must stay plausible.
- National ID = learner identity; locked (409) once any outbox row exists for the child. Fixing a wrong locked ID is an admin-side gap (proposed follow-up).

## Live-class attendance pipeline
- Live-class attendance goes through the same production outbox as self-paced learning; the `attended` verb is NOT part of the staging parity journey — never validate it against those contracts. Attendance is deduped per session activity IRI because the LRS is append-only: no retractions, so a status flip-flop must never re-send.
- Two learner-identity fields exist by design (self-paced child vs live-class student) — the same person may hold both; any national ID locks once statements were queued under it. Only genuinely-present marks count; adding an ID later backfills each past attended session individually.
